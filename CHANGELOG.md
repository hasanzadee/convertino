# Changelog

## Unreleased

- **Live preview.** Hover a petal and the flower's centre turns into a lens showing the result (B&W, Square, Rounded, Half, the AI cut-out on a checkerboard…), with its size and change (`249 KB · −84%`, `3840×3840 · 1.04 MB`); format petals show what each file would weigh, so you can see that AVIF is 127 KB and PNG 4.4 MB before choosing. Estimates (`≈`) appear within ~0.1 s from the real action run on small copies; exact sizes follow from a full run in a temporary sandbox, which starts by itself for format petals on ordinary photos and after a short hover for the rest (Cut out after a longer one). Dropping on a petal whose run is done moves its result into place at once (9 ms instead of seconds); a run still going is picked up instead of starting over. Pictures only for now; on all three platforms. **Live preview** in the panel turns it off; `convertino preview <images> [--full] [--take <petal>]` shows the same from the command line.
- **Recipes**: a chain of petals as one petal, e.g. *Web-ready* = Full HD → WEBP → Clean, *Email PDF* = PDF → Compress, *Insta square* = Square → JPG. They sit on a **Recipes** ring right after Convert, showing only those whose every step works on the dragged files. The steps run on copies in a temporary folder, so only the final result lands (`photo (Web-ready).webp`); progress is split across the steps, cancelling removes everything, and a failing step names itself (*Web-ready stopped at step 2: WEBP*). A recipe is checked when it's saved: each step has to take what the one before makes (no image tool after → PDF, clipboard petals only last), and without a file type it's worked out from the steps.
- **Recipes card** in the tray / menu-bar panel (Windows, Linux, macOS): your recipes with their steps as chips, one-click templates (*Web-ready*, *Email PDF*, *Insta square*, *Podcast*; only those that work on this computer), a builder (pick a kind of file, add steps from the ones that fit at that point, name, icon), change or delete, and **recipes.json** for custom commands. The card stays folded until clicked.
- **Custom commands**: your own programs as petals, in `recipes.json`: `program` (on PATH or a full path), `args` with `{in}` `{name}` `{ext}` `{dir}` `{out}`, the `output` it makes, `for` and `timeout`. Run once per file with the arguments passed one by one (no shell, no command line built from strings, so file names can't inject anything; on Windows only `.exe` / `.com`, nothing that goes through cmd.exe). A result has to be new: a command whose output would be the file itself, its folder or an existing file isn't run, so cancelling or Save results never touches anything that was already there, output to the log, a non-zero exit shows its last line, a missing program says *ffmpeg not found*. A command that makes a file can be a recipe step.
- **Save results**: next to the original (default), in a subfolder of its folder, or in one fixed folder, for every petal that makes a file when you drop on it; a recipe can pick its own place (`"out"`). On the command line results stay next to the original unless `--out <subfolder|path>` is given (`convert`, `run`, `recipe run`). Editors, clipboard petals, *Extract here* and *Join* keep their place; watch folders keep their own `Converted` folder.
- Command line: `convertino recipe list | add <name> --steps a,b,c [--for jpg,png] [--out …] [--icon …] | remove <name> | run <name> <files…>`; `convertino actions` lists the `recipes:` that fit (custom commands too), and `convertino run recipe-<name> …` works like any petal.
- `CONVERTINO_APPDATA=<folder>` keeps the settings, lists and log in another folder (tests, a portable copy).
- Linux: text boxes in the panel get the keyboard (the panel is an override-redirect window that no window manager focuses).

## 1.3.0 — 2026-10-20

The biggest release so far: new formats, a ring of one-tap image tools, data and subtitle conversions, archives beyond ZIP, PDF tools and folders that convert by themselves. Every part was reviewed for safety (path traversal and decompression bombs in archives, alias bombs and deep nesting in YAML/XML, formula injection in CSV) before release.

- Images get two more rings after Tools: **More tools**, with **Half**, **Full HD** (shrinks to fit 1920 × 1080, or 1080 × 1920 for portrait; never enlarges) and **B&W** in one tap, and **More formats**: **HEIC** (where the codec allows), **TIFF**, **ICO**, **BMP**, **JPEG XL** and **QOI**. Half, Full HD and B&W keep the source's format (PNG for SVG/PSD/TGA, JPG for camera RAW), keep animated GIF / WebP animated, and write beside it as `photo (2016x1512).jpg` / `photo (grayscale).jpg`. The Convert ring now holds the everyday formats: PNG · JPG · WEBP · AVIF · PDF · **GIF**. `.qoi` files are recognised as images.
- Flip the rings with **Tab** / **Shift+Tab** and the **mouse wheel** (down = next, up = previous) as well as the trigger key, on all three platforms, mid-drag and in click mode. The rings wrap around (Convert → Tools → More tools → More formats → Convert, so wheel up from Convert reaches the rarer formats), the centre names the ring for a moment after each flip, and a touchpad swipe or a fast spin counts as one flip. No ring shows more than 10 petals: a longer list carries on in a second ring. The trigger key now flips when it comes back up, so Shift+Tab goes back instead of also counting the Shift. Windows: Tab and the wheel over the flower don't reach the window behind it, while Alt+Tab, Win+Tab and Ctrl+Tab stay the system's (unless that modifier is the trigger key). Linux and macOS only watch Tab and the wheel, so the app behind sees them too (in Linux click mode Tab also moves the file manager's focus). Linux: the wheel is read through XInput2 raw events, so it works while the file manager holds the drag. macOS: Tab during a drag needs Input Monitoring (like Esc); the flower's own window always sees it in click mode.
- `convertino actions` lists the new rings (`more:`, `formats:`); `Convertino.exe --snapshot out.png <theme> more|formats` renders them, and `Convertino.exe --paging-selftest <dir>` runs the wheel / Tab / Shift paging through the real hook callbacks and overlay without touching the desktop.
- PDF tools ring: **Compress** (re-distilled with Ghostscript when it's installed; the result is kept only if it's smaller), **Images** (every embedded picture at its original quality, duplicates skipped), **Numbers** ("3 / 12" at the bottom of each page, upright on rotated pages, no font files needed) and **Cover** (the first page as PNG).
- Watch folders: pick a folder in the panel ("Watch a folder…") and what new files become (PDF, JPG, PNG, WEBP, Compress, Clean); everything that lands there is converted into its `Converted` subfolder, with a result card. Partial downloads (`.part`, `.crdownload`, …) are waited out. Also from the command line: `convertino watch <folder> --to pdf` in the foreground, or `convertino watch add | list | remove` for the desktop app, which picks up changes immediately.
- Fixed: images → PDF failed with "Unsupported image format" for JPEGs that don't start with a JFIF/Exif segment (Windows' own wallpapers, many camera exports).
- Subtitles: SRT, WebVTT, ASS and SSA files (and LRC lyrics) convert into each other and to plain text. Timestamps stay to the millisecond (ASS itself counts hundredths); line breaks, italics, bold and top-of-screen cues ({\an8}, `line:0`) carry over, and ASS styles, positions and drawings are dropped. Each conversion is written as UTF-8 and reads legacy encodings correctly.
- **UTF-8** tool for every plain-text file (TXT, Markdown, CSV/TSV, JSON, YAML, XML, INI, HTML, scripts, subtitles…): re-encodes Windows-1251/1252/1254, KOI8-R, DOS 866, the system code page and UTF-16/32 as UTF-8 (BOMs are honoured; otherwise the encoding is detected, and a UTF-8 file with a stray invalid byte stays UTF-8). Only the encoding changes, line endings included. It writes `notes (UTF-8).txt` and says *Already UTF-8* when there's nothing to fix; a UTF-8 CSV without a BOM gets one so that Excel reads it as UTF-8. **Copy contents** uses the same detection, so legacy text pastes correctly.
- **LF** / **CRLF** tools for the same files: the petal offers the line ending the file doesn't use (both when it mixes them) and writes `run (LF).sh`; the encoding is left exactly as it was, UTF-16 included, and on Linux and macOS the copy keeps the file's permissions (a script stays executable). Files on network shares, offline files and cloud placeholders aren't read while the flower opens; they get both petals.
- Files with NUL bytes (anything but UTF-16/32) count as binary: the text tools aren't offered for them and refuse to touch them.
- **Subtitles** tool for videos (with ffmpeg): saves the first text subtitle track beside the video as SRT (`movie.eng.srt`), with ASS styles dropped. It says so clearly when the video has no subtitle track, or only picture-based ones (PGS, VobSub).
- **Archives**: Extract now opens 7Z, RAR (RAR4, RAR5, solid and multi-volume `.part1.rar`), TAR, TAR.GZ / TGZ, TAR.BZ2, TAR.XZ and single GZ / BZ2 / XZ files, besides ZIP, with progress and cancel. Archives unpack into a new folder beside them (`foo.zip` holding just `foo/` gives `foo`, not `foo/foo`); a single compressed file (`notes.txt.gz`) lands beside it as `notes.txt`. Entries that would land outside the folder (`../`, absolute paths, drive letters, UNC) are refused, symbolic and hard links in archives are skipped, and both are counted on the card (*2 unsafe entries refused · 1 link skipped*). Names Windows can't store (`con.txt`, `CONIN$`, `what?.txt`) get a safe name, and two entries that end up with the same name (`A.txt` / `a.txt`) both survive as `a (2).txt`. An archive that would unpack to more than 200 times its size (at least 4 GB), or leave less than 1 GB free on the disk, is stopped as a decompression bomb. Archives unpack into a hidden working folder that is renamed at the end, so nothing that was already there is ever touched or cleaned up. Password-protected archives say so.
- **Pack as 7Z or TAR.GZ**: folders (and several files) get **7Z** (LZMA2, the smallest, slower) and **TAR.GZ** (keeps links and Unix permissions) next to **Zip**.
- **Split / Join**: big files (over 10 MB) get split petals on the Tools ring with sizes that fit them (25 MB · 50 MB · 100 MB …, 4 GB for FAT32), writing `name.ext.001`, `.002` … and a `name.ext.sha256` of the whole file beside it. Drop the `.001` and **Join** puts the original back together after checking that no part is missing or cut short, and that the result matches that `.sha256` (without one, a full-size last part is refused, since parts after it may be missing).
- **Duplicates**: drop a folder (or several files) on **Duplicates** to find identical files (same size, then same SHA-256). The card shows *N duplicate groups · X MB* and an HTML report beside the folder lists every group and the space it wastes. Nothing is ever deleted; hidden / system files, links and online-only OneDrive files are left out.
- **Checksums**: drop a file together with its `.sha256` / `.sha1` / `.md5` / `.sha512` or a `SHA256SUMS`-style list and **Verify** shows *Matches ✓* or *Doesn't match ✗* (a list on its own checks the files it lists in its own folder, like `sha256sum -c`, ignoring any line that points elsewhere: `../`, absolute, drive or UNC paths; GNU, BSD and bare-hash formats). SHA3, BLAKE2 and SHA-224 lines say they can't be checked instead of failing. Archives and other files get **MD5**, **SHA-1** and **SHA-512** on the Tools ring next to the SHA-256 petal. `convertino run verify` exits with 1 on a mismatch.
- **CSV / XLSX → Markdown and HTML tables**: one table per non-empty sheet under its name, number columns right-aligned, pipes and Markdown punctuation escaped, and UTF-8 kept (no HTML entities for non-ASCII). With an office suite, *HTML* on CSV / XLSX is now this clean table rather than Excel's export.
- **Pretty** and **Minify** for **CSS**. They touch only whitespace and comments (licence `/*! */` comments stay), so `a :hover`, `calc(1px + 2px)`, strings and `url(…)` keep their meaning.
- Data files get their own rings: **JSON, JSON Lines, YAML, TOML and XML** convert into one another and to **CSV** and **XLSX**, and JSON and XML get **Pretty** and **Minify**. Round trips keep the data: YAML is read as YAML 1.2 (`yes` / `no` stay text) and written so YAML 1.1 readers agree, TOML dates stay dates, numbers keep their spelling, and XML attributes, repeated elements and namespaces map to `@name`, lists and `p:name`. The rules are in [docs/data-formats.md](docs/data-formats.md).
- CSV output neutralises formulas: text cells starting with `=`, `+`, `-`, `@`, a tab or a CR get a leading `'`, so they open as text in Excel and LibreOffice instead of running. Numbers such as `-5` are untouched, and Convertino's own CSV reader removes the `'` again.
- Malicious data files can't hang or crash the app. A YAML "alias bomb" is refused once it expands past 2 million values. JSON, YAML and XML trees nest at most 512 levels, and XML entity expansion is capped.
- **CSV ⇄ XLSX** and **CSV / XLSX → JSON** now work without Microsoft Office or LibreOffice, on every platform. They keep UTF-8 (Excel reads a CSV without a BOM in the ANSI code page) and every sheet: one CSV per sheet, or `{"Sheet1": […], "Sheet2": […]}` in JSON. Office still handles PDF, ODS and HTML.
- **Image tools**, one tap each, no questions asked, results saved beside the source:
  - **Messenger**: long side at most 2560 px, JPEG quality 85, turned upright from EXIF, colours baked into sRGB, every tag removed including the GPS location (the card says so).
  - **Square**: a 1:1 canvas with the photo centred over a blurred, enlarged copy of itself.
  - **Rounded**: rounded corners and a soft drop shadow on a transparent PNG, for screenshots in docs and READMEs. A window capture with a transparent margin is trimmed first, so the shadow follows the window.
  - **Palette**: the 5–8 dominant colours as HEX on the clipboard, one per line, plus a swatch strip PNG. A flat logo gives just its own colours, not the blends along its edges.
  - **Favicon**: a folder with `favicon.ico` (16/32/48), `apple-touch-icon.png` (180, on white since iOS paints transparency black), `icon-192.png`, `icon-512.png`, `site.webmanifest` and `snippet.html` with the `<link>` tags. SVG logos are rendered sharp at every size.
  - **Copy** (image): puts the picture itself on the clipboard, not the file, so it pastes straight into chats and documents. Windows offers PNG (keeps transparency) plus a plain bitmap, macOS PNG plus TIFF; Linux hands it to `wl-copy` (Wayland) or `xclip` (X11). Pictures longer than 4096 px are scaled down to that first, and the card says so.
  - **Read QR**: copies the text of the QR code(s) in an image, also small, inverted (dark mode) or photographed ones; Data Matrix and Aztec codes too. **QR** on a `.txt`, `.url` or `.webloc` makes a QR code PNG of its text or link (UTF-8, so non-Latin text scans correctly).
  - For several images: **Contact sheet** (one JPG grid of thumbnails with file names, up to 400 images), **Slideshow** (a GIF and an animated WEBP of up to 60 pictures, sorted by name, 1 s per frame, letterboxed to one size) and, for exactly two of the same proportions, **Compare** (the changes in red and boxed, and *N% of pixels differ* on the card). When files are left out, the card says *first 60 of N*.
- 1-bit images (QR codes, line-art scans) reached the editors and tools bit-packed; they're read as normal 8-bit pixels now.
- Windows: when the clipboard can't be opened (another app holds it, or the screen is locked) the card now says so instead of claiming the text was copied.

## 1.2.0 — 2026-10-20

Thanks again to [@AliverdiSultanli](https://github.com/AliverdiSultanli) for the trigger keys, the update check and the macOS Quit fix, all tested on his Mac.

- Choose the key that opens the flower: **Open with** → Shift (default), Shift twice, Ctrl or Alt (Control / Option on macOS), in the tray panel and the tray / menu-bar menu. Hints and the Explorer drag caption follow the key. *Shift twice* leaves a single Shift to apps that use it on drop, such as Claude, which attaches a file on Shift + drop (#6).
- Know when a new version is out: **Check for updates…** in the menus and **Updates** in the panel footer, plus an optional daily check. It's off until you answer a one-time *Notify about updates?* card; it only reads the latest release from GitHub, sends nothing else, and never downloads or installs anything (#11).
- macOS: **Quit Convertino** froze the app until it was killed (#8).
- macOS: Activity Monitor and Force Quit listed the app as *Avalonia*; it's *Convertino* now (#10).
- Activity card on Linux and macOS: a new panel opens from the tray icon (Linux) or **Open panel** in the tray / menu-bar menu, with the same counting-up numbers, a bar per day that shows that day's numbers on hover, and your most used actions; until you've converted something it shows how to start. It closes on Esc, a click outside or ✕. `CONVERTINO_PANEL=1` (or `=demo`) opens it at start, for screenshots.
- The Linux and macOS panel now has everything the Windows one has: the four theme swatches (switching restyles everything at once and is remembered), the Enabled / Notifications / Tell me about new versions / Start at login (Open at login on macOS) switches, the **Open with** key picker (Shift, Shift ×2, Ctrl/Control, Alt/Option), your recent files with thumbnails, and Log / Updates / Quit. **Open panel** is now the first item of the tray / menu-bar menu, and the menu follows what you change in the panel (it is refreshed in place; the tray icon is no longer re-created on a theme change).
- macOS: a click on the menu-bar icon opens the panel straight away, like the tray icon on Windows; right-click or Control-click it for the menu. Avalonia's status item can only open its menu, so Convertino takes the plain click itself.

## 1.1.1 — 2026-10-20

Fixes from [@AliverdiSultanli](https://github.com/AliverdiSultanli), who also ran the first test of Convertino on a real Mac (M4, macOS 27). Thank you!

- Zip: a folder passed with a trailing slash (`photos/`, shell tab completion on Linux and macOS) was zipped into itself as `.zip` and its entries lost the folder prefix; a folder with dots in its name (`release.v2`) came out as `release.zip`. Both fixed (#2).
- Compress: images with real transparency (ICO, TGA, PSD, SVG, …) came back as JPEG on white; they now stay PNG with their alpha. Images with an alpha channel that is fully opaque go to the smaller JPEG (#3).
- Settings: `settings.json` is written to a temporary file and swapped in, behind one lock, so a crash or a second process can never see half a file and reset your theme, toggles and recent list (#4).

## 1.0.0 — 2026-10-19

First public release.

- Drag any file and tap Shift: the radial menu blooms under the cursor (Windows OLE drag & drop, Linux XDND, macOS Finder drops).
- Convert and Tools rings, flip with Shift; drag captions in Explorer; drops always copy, never move.
- Images, PDF, Word/Excel/PowerPoint (Microsoft Office or LibreOffice), Markdown, text, video, audio, ZIP, folders.
- Editors: Crop, Add BG, Annotate, Redact (with automatic text detection), Adjust.
- Cut out: offline AI background removal (BiRefNet-lite; DirectML GPU on Windows, CPU on Linux and Apple silicon).
- OCR to clipboard (Windows OCR / Vision / Tesseract), lossless metadata cleaning, smart compression.
- Double-tap Shift in Explorer and Send to → Convertino (Windows); right-click → Convertino in Nautilus, Nemo, Dolphin, Caja (Linux); Finder Quick Action (macOS).
- macOS app (13 Ventura or later, Apple silicon and Intel): system blur glass, CoreGraphics PDF rendering, Vision OCR, menu-bar icon, LaunchAgent. Ad-hoc signed, not notarized. **Beta:** the drag + Shift gesture is verified in CI with synthetic input, not yet on real hardware.
- Command line: `convertino convert | run | actions | menu | model`.
- Themes: Catppuccin Mocha & Latte, Sunset, Graphite.
